# Project architecture

- Some subdirectories have their own `AGENTS.md`; read it before changing files there.
- The shared loading mark animates separate HTML compositor layers around static SVG artwork rather than SVG groups, avoiding per-frame SVG painting during native embed loading.
- Home opening slots use a presentation-only whole-card gate, load mounted children concurrently, and reveal in feed order; native ads reserve their opening slot and fade their complete SDK overlay after presentation, without altering protected playback/scoring or feed refresh rules.
- Home keeps a stable session snapshot: mutation/realtime invalidations never refetch it, loading readiness never reorders it, and foreground recovery distinguishes actual background return from iframe focus/network events so only app entry or explicit top refresh replaces it.
- Native startup keeps the OS launch screen logo-free (`scripts/blank-native-splash.mjs` in `assets:generate`, since `android/` is local-only), then hands off to the animated HTML splash after the bounded native hide completes.
- Media lifecycle is keyed by post and playback generation: play candidates remain repeatable after rejected swipe gestures, every confirmed play synchronously arms that post, and starting another video immediately pauses the previous one; score deduplication must never consume lifecycle detection.
- Platform-specific block viewers keep only the landed post's player mounted and use empty scroll-snap neighbours for motion; fresh selection matches a direct grid opening without changing shared embed/scoring logic, while other viewers retain full-list anchored scrolling.
- Grid position uses a read-only dial derived from rendered post ranks, isolated from media lifecycle and persistence so displaying position never records activity.
- `public/` holds runtime artwork plus a deliberately restored, unreferenced set (`public/splash/*`, `promo-banner.png`, `onboarding-hero.png`, `error-state.png`) kept at the owner's request to raise app size; don't delete it as "unused" without asking. Native icon/splash generation reads `resources/`, never these files.
- Both post renderers use the shared visibility-gated liked-by summary with viewer-scoped query caches and existing RLS-protected reads; social context stays separate from media lifecycle and scoring.
- Both source-validation entry points share Instagram evidence and restoration cleanup; scheduled rechecks remove only source-deletion notices after positive availability evidence, never moderation notices or posts.
- iOS lives in committed `ios/` (SPM); local plugins in `capacitor-plugins/` need a `Package.swift` with `CAPBridgedPlugin`; Xcode targets/entitlements/Share Extension are applied by `scripts/ios/configure-xcode.rb` in `codemagic.yaml`, since Linux sandboxes can't edit Xcode targets reliably.
- Native ID-token sign-in needs a client ID the backend holds; Cloud stores only the web Google ID, so iOS GoogleSignIn uses it as `iOSServerClientId` with a hashed nonce, falling back to browser OAuth if refused; Android uses Credential Manager. The sign-in page navigates explicitly after the exchange, and only a real back-out is a cancel (`socialSignInError.ts`): Credential Manager can say "cancelled"/"no credentials" after an account was picked.
- iOS (capacitor://) matches no `frame-ancestors *`: YouTube iframes relay via the website (`src/lib/iosEmbedRelay.ts`, `public/embed-relay.html`); Reddit/LinkedIn can't be relayed (WebKit checks every parent), so iOS fetches Reddit JSON natively (`src/lib/redditPostData.ts`).
- Reddit blocks server JSON lookups; servers fall back to `_shared/redditPublic.ts`; refreshes never overwrite stored thumbnails/text with empty/generic text.
- `getUser()` is wrapped once in `src/lib/authResilience.ts`: an unexpired local session answers without a network round trip (RLS still verifies every request), and a transient server miss renews the session instead of surfacing "Not authenticated".
- Keep `@supabase/supabase-js` >= 2.118 (lockless auth): older versions serialised requests behind a `navigator.locks` lock held across `getUser()` network calls, making iPhone screens wait seconds.
- Post-author lookups go through `src/lib/authorProfile.ts`, which retries and throws instead of resolving empty, and the query persister never stores null data, so a passing network failure can't be cached as an "Unknown" author.
- Incoming shared links are routed only by `useShareTarget`/`shareTarget.ts` (the composer itself is protected): links wait for a signed-in session off the sign-in page, expire after a short TTL, and an already-open composer is closed and reopened so it consumes the new link; the iOS Share Extension opens the app only when it finds an http(s) link.
- Codemagic runs `npm ci` with `npm install` fallback because bun-managed `package-lock.json` drifts; after dependency changes run `npm install --package-lock-only` and rewrite sandbox `resolved` URLs to `https://registry.npmjs.org/`.
- Keyboard layout: Android relies on native WebView resizing (`--kb` stays 0, events only toggle `kb-open`); iOS keeps `resize: "none"` and sets `--kb` from the plugin's keyboard height, because Keyboard `resize` is iOS-only and leaves the iPhone WebView full height.
- Chat threads retry failed loads silently with backoff and refresh on app return/online; an error state appears only when nothing cached can be shown, because transient post-resume network drops were surfacing as false "Failed to load" toasts.
- People search (`src/lib/profileSearch.ts`): trim queries (iOS predictive text adds a space), short deadline with retries per attempt (stale iOS connections hang ~60s), only the newest reply may update the screen; earlier-letter results show instantly.
- The conversation list (`useConversations`) must never write on every fetch: delivered marks only for newer incoming messages, refetch on own participant-row updates only when read state changed (a blanket write + refetch looped endlessly).
- App-wide realtime listeners must be filtered to the signed-in person's own rows (only post INSERT/DELETE stay global): unfiltered listeners are billed per online user per change and refetch on every screen.
- Chat sends are optimistic through `src/lib/messageOutbox.ts`: client-generated id before insert, per-chat outbox until server confirms, duplicate-id error counts as delivered — retries/restarts can never post twice.
- Native ad overlays (`NativeFeedAd.tsx`) follow their slot every animation frame (bridge call only on change), move off-screen whenever the slot is hidden or a dialog is open, and destroy via an id ref on unmount, because the native card paints above the whole WebView and stale/leaked overlays covered posts and other tabs.
- Multiple accounts go through `src/lib/accountSwitcher.ts` (list rules in `accountStore.ts`): switching restarts the app with the persisted cache discarded, saved tokens are refreshed before `setSession`, and logout removes only this device's push registration, because caches and push tokens are shared on one phone.
- Mutes are enforced where notifications are created (database triggers skip muted accounts/chats), so phone and in-app alerts stay consistent on every app version without client checks.
- Forced updates: `ForceUpdateGate` compares the native build with `remote_flags` `force_update_*` (enabled + min_build); errors/unknown builds never block, so outages cannot lock users out.
- Phone alerts auto-dismiss: the push sender stamps new-post/chat pushes with a dismiss key from their URL (`_shared/pushDismissKey.ts`; Android FCM `tag`, iOS `dismissKey`), and `dismissNativeNotification.ts` removes them when the post is seen or the chat opens; the native method lives in the GamNative plugin to skip new Xcode/Gradle wiring.
- Deactivation is a `profiles.deactivated_at` flag enforced by the database (profile read policy, `are_blocked`, feed functions) and cleared on the owner's next sign-in by `useReactivateOnSignIn`; permanent deletion goes only through the `delete-account` function, which must be extended whenever a new table stores a person's rows.
