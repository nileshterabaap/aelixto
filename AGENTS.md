# Project architecture

- The shared loading mark animates separate HTML compositor layers around static SVG artwork rather than SVG groups, avoiding per-frame SVG painting during native embed loading.

- Home opening slots use a presentation-only whole-card gate, load mounted children concurrently, and reveal in feed order; native ads reserve their opening slot and fade their complete SDK overlay after presentation, without altering protected playback/scoring or feed refresh rules.

- Home keeps a stable session snapshot: mutation/realtime invalidations never refetch it, loading readiness never reorders it, and foreground recovery distinguishes actual background return from iframe focus/network events so only app entry or explicit top refresh replaces it.

- Native startup keeps the OS launch screen logo-free (patched by `scripts/blank-native-splash.mjs` inside `assets:generate`, since `android/` is local-only) until the WebView paints, then hands off to the animated HTML splash; its visible interval starts after the bounded native hide/fade completes so slow bridges cannot hide the animation.
- Media lifecycle is keyed by post and playback generation: play candidates remain repeatable after rejected swipe gestures, every confirmed play synchronously arms that post, and starting another video immediately pauses the previous one; score deduplication must never consume lifecycle detection.
- Platform-specific block viewers keep only the landed post's player mounted and use empty scroll-snap neighbours for motion; fresh selection matches a direct grid opening without changing shared embed/scoring logic, while other viewers retain full-list anchored scrolling.
- Grid position uses a read-only dial derived from rendered post ranks, isolated from media lifecycle and persistence so displaying position never records activity.
- `public/` holds runtime artwork plus a deliberately restored, unreferenced set (`public/splash/*`, `promo-banner.png`, `onboarding-hero.png`, `error-state.png`) kept at the owner's request to raise app size; don't delete it as "unused" without asking. Native icon/splash generation reads `resources/`, never these files.
- Both post renderers use the shared visibility-gated liked-by summary with viewer-scoped query caches and existing RLS-protected reads; social context stays separate from media lifecycle and scoring.
- Both source-validation entry points share Instagram evidence and restoration cleanup; bounded scheduled rechecks remove only source-deletion notices after positive availability evidence, never moderation notices or the posts themselves.- iOS lives in committed `ios/` (Swift Package Manager); local plugins under `capacitor-plugins/` must ship a `Package.swift` with `CAPBridgedPlugin`, and Xcode targets/entitlements/Share Extension are applied by `scripts/ios/configure-xcode.rb` in `codemagic.yaml`, because Linux sandboxes cannot edit Xcode targets reliably.

- Native ID-token sign-in only works for a provider whose client ID the backend holds; Lovable Cloud stores a single Google client ID (the web one), so iOS GoogleSignIn sets the web ID as `iOSServerClientId` (token minted for it) with a hashed nonce, and falls back to the browser OAuth flow if the exchange is refused; Android keeps Credential Manager.
- The iOS app origin (capacitor://) sends no Referer and matches no `frame-ancestors *`: YouTube iframes are rewritten app-wide (`src/lib/iosEmbedRelay.ts`) to the website relay `public/embed-relay.html`, which forwards postMessage both ways; Reddit's and LinkedIn's players use `frame-ancestors *`, which WebKit checks against every parent frame, so no relay can host them; on iOS the phone fetches Reddit's public post JSON natively (`src/lib/redditPostData.ts`, CapacitorHttp) and draws a Reddit-style card, falling back to the preview card.
- `getUser()` is wrapped once in `src/lib/authResilience.ts`: an unexpired local session answers without a network round trip (RLS still verifies every request), and a transient server miss renews the session instead of surfacing "Not authenticated"; protected callers benefit without edits.
- Stay on a `@supabase/supabase-js` version with lockless auth (>= 2.118): older versions serialised every request behind a `navigator.locks` auth lock held across `getUser()` network calls, which made iPhone screens wait seconds.
- Post-author lookups go through `src/lib/authorProfile.ts`, which retries and throws instead of resolving empty, and the query persister never stores null data, so a passing network failure can't be cached as an "Unknown" author.
- Incoming shared links are routed only by `useShareTarget`/`shareTarget.ts` (the composer itself is protected): links wait for a signed-in session off the sign-in page, expire after a short TTL, and an already-open composer is closed and reopened so it consumes the new link; the iOS Share Extension opens the app only when it finds an http(s) link.
- Codemagic installs with `npm ci` and falls back to `npm install`, because Lovable manages dependencies with bun and `package-lock.json` can drift; refresh it with `npm install --package-lock-only` after dependency changes, then rewrite any sandbox-registry `resolved` URLs to `https://registry.npmjs.org/` (Codemagic can't reach the sandbox cache).
- Keyboard layout: Android relies on native WebView resizing (`--kb` stays 0, events only toggle `kb-open`); iOS keeps `resize: "none"` and sets `--kb` from the plugin's keyboard height, because the Keyboard `resize` option is iOS-only and leaves the iPhone WebView full height.
- Chat threads retry failed loads silently with backoff and refresh on app return/online; an error state appears only when nothing cached can be shown, because transient post-resume network drops were surfacing as false "Failed to load" toasts.
- People search goes through `src/lib/profileSearch.ts`: queries are trimmed (iOS predictive text appends a space), each attempt has a short deadline with retries (stale iOS connections can hang ~60s), only the newest reply may update the screen, and earlier-letter results show instantly while the server answers.
- The conversation list (`useConversations`) must never write on every fetch: it writes delivered marks only for newer incoming messages and refetches on its own participant-row updates only when read state changed, because a blanket write + realtime refetch formed an endless request loop on every screen.
- App-wide realtime listeners must be filtered to the signed-in person's own rows (only post INSERT/DELETE may stay global), because every unfiltered listener is delivered and billed per online user per change and triggers refetches on every screen.
- Chat sends are optimistic through `src/lib/messageOutbox.ts`: each message gets its client-generated id before the insert, is kept in a per-chat local outbox until the server confirms it, and a duplicate-id error counts as delivered, so retries and app restarts can never post a message twice.
- Native ad overlays (`NativeFeedAd.tsx`) follow their slot every animation frame (bridge call only on change), move off-screen whenever the slot is hidden or a dialog is open, and destroy via an id ref on unmount, because the native card paints above the whole WebView and stale/leaked overlays covered posts and other tabs.
- Multiple accounts go through `src/lib/accountSwitcher.ts` (list rules in `accountStore.ts`): every signed-in session is saved locally, a different active account always restarts the app with the persisted query cache discarded, saved tokens are refreshed before `setSession` so a dead account can't sign out the current one, and logout deletes only this device's push registration for that account, because caches and push tokens are otherwise shared across accounts on one phone.
